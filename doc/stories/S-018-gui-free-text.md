# S-018: gui-app — free text elements

## Why

FR10: independent text objects placed anywhere on the grid, editable in place; they render through the same pipeline (C2) so exports always match the canvas.

## Dependencies

- S-013 — selection/move gestures to reuse
- S-006 — text-object rendering in the place stage

## Acceptance criteria

1. **AC1 — Place + edit.** A "text" tool places a `TextInstance` at the clicked cell; double-click (or equivalent, recorded in Implementation notes) opens inline editing of its content; Enter/blur commits via the aggregate. Check: unit tests of the text gesture handler with fakes asserting `place_text`/content mutation.
2. **AC2 — Move like shapes.** Text objects are selectable and draggable with the same grid-snap rules as shapes (FR7). Check: unit test reusing the S-013 drag handler on a text object.
3. **AC3 — Render parity.** The edited content appears in `render` output byte-identically to what the canvas shows, including label-escaping edge cases from S-003 (quotes, long labels). Check: unit test comparing canvas grid bytes with `Exporter::to_text`.
4. **AC4 — Gates green.** fmt/clippy/test pass; `cargo tarpaulin -p gui-app` ≥ 80%; wasm check still exits 0.

## Implementation notes

The S-012…S-017 pattern: pure interaction logic in `gui-app` (headless-tested), thin egui glue in `app.rs`, model mutations only through the aggregate.

- **Model (`diagram-model`):** new `Diagram::set_text(&id, content)` — the aggregate operation for content edits; typed errors for unknown ids, non-text targets and empty content. `TextInstance::stamped_lines()` applies the C1 F4 quote fallback per line (lines containing any svgbob-alphabet glyph are wrapped in double quotes) — moved *into* the model so rendering and GUI hit-testing share one definition; new `glyphs.rs` holds the shared alphabet predicates (`is_line_glyph`, `is_arrowhead`, `is_svgbob_glyph`), which `render-pipeline` now delegates to (no behavior change).
- **Gesture machine (`gui-app/src/editor.rs`):** `placing: Option<ShapeInfo>` generalized to `Placing::{Shape(ShapeInfo) | Text}`; new `PointerEvent::DoubleClick` and outcomes `PlacedText` / `Editing` / `Edited`. Placement with the text tool places a placeholder object and opens inline editing in one gesture (the model rejects empty content, so a placeholder is required — it is replaced immediately). Double-click on a text body opens editing of its current content; shapes are not inline-editable in v1. While editing: a pointer press commits (blur semantics) and consumes the click; Escape cancels without mutation; an empty draft cancels instead of committing (the model rejects empties). The Move gesture now handles `Text` bodies identically to shapes (`HitTarget::Shape` → `Body`; grid-snap, grab-offset, origin clamp all unchanged).
- **Canvas (`gui-app/src/canvas.rs`):** hit-testing covers text via its stamped extent — new `text_hit_extent()` (per-line max width × line count of `stamped_lines`).
- **GUI glue (`gui-app/src/app.rs`):** sidebar gains a “T  Text” tool above the Shapes heading; while editing, a floating `egui::Area` hosts a multiline `TextEdit` bound to `EditorState::edit_draft`, positioned over the object’s cells. Plain Enter commits (checked *before* the field is shown so egui does not insert a newline first); Shift+Enter inserts line breaks; blur or pointer press commits; Escape cancels (via `on_escape`, which checks the edit first). While editing, Delete/Backspace are guarded out of `handle_key_frame` — they belong to the text field, not object deletion. The field requests keyboard focus **every frame while editing** (it appears without a click): egui attributes the opening click to the canvas — installed before the editor's `Area` exists — and surrenders the field's focus on the release frame, so focus-once made the editor commit the placeholder and close immediately after placement. Two refinements from the deep-glue analysis (2026-10-29): the re-request *yields* while another text edit holds focus (a later-drawn field's `request_focus` overwrites earlier ones — without yielding, the canvas draft stole the keyboard back every frame from the path prompt / template-editor fields), and it is *skipped on the frame the user clicked away* (egui's `SurrenderFocusOn::Clicks` surrender runs inside the widget's own `interact`; re-requesting right after would undo it). Conversely, any text field that **gains** focus while an edit is open commits it — blur semantics per AC1, including the path prompt and both template-editor fields (Escape-press frames are exempt so a fast Escape closing a dialog does not commit as a side effect). The pointer-blur-commit path (`lost_focus` guard) is suppressed on pointer frames and while another text edit holds focus for the same reasons; note egui's `lost_focus` uses a two-frame memory, so it fires one frame *after* focus moved.
- **Bug fix (pre-existing since S-012):** the canvas drew the trimmed grid text with the vertical content-origin offset but *not* the horizontal one — for any diagram whose content does not start at column 0, rendered cells sat left of the model/hit-test space (clicks on drawn objects hit empty cells). Both axes are now offset; the fix is pinned by `the_text_sample_fixture_loads` (box at x=3 renders with origin_x applied).
- **Bug fix (found by the headless GUI integration suite, 2026-11):** clicking to place text opened the inline editor for one frame, then the placeholder was committed and the editor closed on mouse-up — egui's focus surrender (see focus note above). Fixed by per-frame `request_focus()` + guarded blur-commit; pinned end-to-end by `gui_tests::text_tool_places_and_inline_edit_commits_on_enter` and `double_click_on_existing_text_reopens_editing`.
- **Bug fix (deep-glue analysis, 2026-10-29):** while an inline edit was open, typing in the path prompt or a template-editor field landed in the *canvas draft* — the inline field's unconditional per-frame `request_focus()` (drawn last in the frame, so its write won) re-stole the keyboard every frame, even right after egui surrendered it for the outside click. Also, Escape with both an edit and a prompt open cancelled the *edit* first (branch order in `handle_global_keys`), discarding the draft while the user was looking at the prompt. Fixed per the focus note above (yield + clicked-away skip + commit-on-gain-focus; Escape now closes the innermost thing — the prompt — first). Pinned by `gui_tests::path_prompt_keeps_the_keyboard_over_an_open_inline_edit`, `escape_while_prompt_opens_closes_the_prompt_not_the_edit` and `template_editor_field_keeps_the_keyboard_over_an_open_inline_edit`. egui 0.37 focus internals that shaped the fix: `request_focus` is an immediate write (last writer per frame wins); the outside-click surrender runs inside `interact()` before our post-`TextEdit` code; `lost_focus(id)` = focused in the previous *or* second-previous frame and not now; a widget's focus is dead-lettered two frames after it stops being drawn.
- **AC1 “or equivalent”:** double-click opens inline editing (the recorded choice); placement also opens it immediately, so content entry never needs a second round-trip.
